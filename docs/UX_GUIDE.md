# UX 가이드

> 이 문서는 **화면이 사용자를 다음 단계로 넘기는 방법**(원칙·단계별 설계·화면 상태·문구)을 다룬다.
> 색·타이포·토큰·컴포넌트 모양은 `docs/UI_GUIDE.md`, 화면별 배치는 `.claude/skills/finsight-design/SKILL.md`, 페르소나·흐름·가설(H1~H8)은 `docs/USER_FLOW.md`가 원본이다. 시각 규칙이 이 문서와 충돌하면 UI_GUIDE가 우선한다.
> 원칙 틀은 Figma의 [UI 디자인 원칙 7가지](https://www.figma.com/ko-kr/resource-library/ui-design-principles/)(계층 구조·점진적 공개·일관성·대비·접근성·근접성·정렬)를 FinSight에 맞게 옮긴 것이다.

## 1. 퍼널 한 장

FinSight의 모든 화면은 아래 6단계 중 하나에 속하고, 각 화면의 역할은 **다음 단계로 넘어가는 행동 하나**를 쉽게 만드는 것이다.

| 단계 | 사용자 머릿속 질문 | 화면 | 다음 단계로 넘어가는 행동 | 측정 |
|---|---|---|---|---|
| 1. 방문 | 나한테 쓸모 있나? 금융 파일을 올려도 안전한가? | 랜딩, 샘플 결과 | `무료로 시작하기` | 페이지뷰 |
| 2. 가입 | 번거롭지 않나? | 회원가입, 인증 메일 안내 | 인증 링크 열기 | `auth.users` |
| 3. 첫 분석 (활성화) | 파일은 어디서 받지? 실패하면? | 대시보드 업로드, 분석 중 | `분석 시작` → 성공 | H1, H2, H4 |
| 4. 결과 이해 | 그래서 뭘 알게 됐지? | 분석 결과 | 잠금 카드 확인, 인사이트 생성 | — |
| 5. 업그레이드 | $9를 낼 가치가 있나? | 잠금 카드, Polar Checkout | `Pro로 업그레이드` → 결제 | H5, H6 |
| 6. 재방문 | 이번 달에도 올릴 이유가 있나? | 대시보드 | 다음 달 명세서 업로드 | H7, H8 |

**가장 중요한 한 단계는 3(첫 분석 성공)이다.** 결과를 한 번 본 사용자만 업그레이드와 재방문으로 간다. 설계 판단이 충돌하면 첫 분석 성공률을 올리는 쪽을 고른다.

## 2. 7가지 원칙을 FinSight에 적용

### 2.1 계층 구조 — 화면마다 주인공 하나

사용자가 첫 시선에 볼 것 하나, 그다음 볼 것을 정해 두고 크기·굵기·여백으로 순서를 만든다.

| 화면 | 1순위 (첫 시선) | 2순위 | 3순위 |
|---|---|---|---|
| 랜딩 | 헤드라인 + `무료로 시작하기` | 히어로 미리보기 카드의 총지출 숫자 | 기능 · 이용 방법 · 요금제 |
| 대시보드 (분석 0건) | 업로드 드롭존 | 샘플 결과 보기 | 사용량 미터 |
| 대시보드 (분석 있음) | 내 분석 목록 | `새 분석` | 사용량 미터, 잠금 카드 |
| 분석 중 | 현재 단계 | 남은 단계 | 기다림 안내 |
| 결과 | 총지출 숫자 | KPI 나머지 3개 · 카테고리별 지출 | 잠금 카드 · 거래 내역 |
| 설정 | 구독 상태 한 줄 | 분석 기록 | 회원 탈퇴 |

- 페이지당 `h1`은 하나. 디스플레이 숫자(Bebas Neue)는 1순위 숫자와 KPI 타일에만 쓴다.
- 텍스트는 3단계(`ink` 주 정보 · `charcoal` 리드 · `mute` 보조)로만 위계를 만든다. 새 회색을 만들지 않는다.
- 1순위 요소는 첫 화면 안에 보여야 한다. 데스크톱 1280×720, 모바일 375×667에서 스크롤 없이 확인한다.

### 2.2 점진적 공개 — 지금 필요한 것만, 다음 것은 다음 화면에서

한 번에 다 보여주면 부담 때문에 포기한다. 단계를 나누고, 사용자가 지금 어디에 있는지와 남은 단계를 알 수 있게 한다.

- **가입에서는 이메일 · 비밀번호 · 필수 동의만 묻는다.** 이름 · 직업 · 쓰는 카드사 같은 온보딩 설문을 넣지 않는다. 첫 분석 전에 묻는 질문은 모두 이탈 지점이다.
- **업로드 화면**: 형식 상세(인코딩 · 1MB · 1,200행)는 드롭존 캡션 한 줄로 둔다. "파일 받는 법"처럼 일부만 필요한 안내는 접힌 상태(`<details>`)로 둔다.
- **분석 중**: 5단계 목록으로 현재 위치와 남은 단계를 보여준다. 마지막 단계에서는 응답을 기다린다.
- **결과**: 요약(KPI) → 분류(카테고리 · 가맹점) → 상세(거래 10행 + `전체 보기`) 순서로 내려간다. AI 인사이트는 사용자가 버튼을 눌렀을 때 만든다.
- **Pro 기능은 숨기지 않고 존재만 공개한다.** 잠금 카드에 발견 건수(티저)만 보여주고 상세는 업그레이드 뒤에 연다.

### 2.3 일관성 — 같은 행동은 같은 말, 같은 버튼

같은 목적지로 가는 버튼은 화면이 달라도 문구 · variant · 아이콘이 같아야 한다. 문구가 바뀌면 사용자는 다른 기능이라고 생각한다.

**CTA 문구 사전**

| 행동 | 문구 | 버튼 | 쓰는 곳 |
|---|---|---|---|
| 비로그인 → 가입 | `무료로 시작하기` | primary (잉크 배경 위에서는 on-image) | 공개 헤더 · 히어로 · 요금제 Free · CTA 밴드 · 샘플 바 |
| 로그인 상태 → 앱 | `대시보드` | primary sm (히어로·요금제·CTA 밴드·샘플 바에서는 그 자리의 `무료로 시작하기`와 같은 버튼) | 공개 헤더 · 히어로 · 요금제 Free · CTA 밴드 · 샘플 바 |
| 샘플 열기 | `샘플 결과 보기` | secondary (soft-cloud 면 위에서는 on-image) | 히어로 · 대시보드 빈 상태 |
| 업로드 영역으로 이동 | `새 분석`(plus 아이콘) / 빈 상태에서는 `파일 올리기` | primary | 대시보드 |
| 분석 실행 | `분석 시작` / `분석 시작 (N개 파일)` | primary | 업로드 |
| 로그인 상태 → 결제 | `Pro로 업그레이드` | primary sm | 잠금 카드 · 업로드 에러 · 한도 도달 · 설정 · 요금제 Pro |
| 결제 관리 | `구독 관리`(external-link 아이콘) | secondary sm | 설정 |
| 인사이트 만들기 | `인사이트 생성` / 실패 후 `다시 시도` | primary sm | 결과 AI 인사이트 |

**용어 사전** — 화면 · 에러 문구 · 랜딩에서 같은 말을 쓴다.

| 쓴다 | 쓰지 않는다 |
|---|---|
| 명세서 (카드 명세서 · 은행 거래내역을 함께 부를 때) | 리포트, 데이터 파일 |
| 분석, 이번 달 분석 N / 5회 | 크레딧, 토큰, 리포트 생성 |
| 정기결제 | 구독 결제, 자동이체 (섞어 쓰지 않음) |
| 이상거래 = 중복 결제 · 급증 | 의심 거래, 사기 |
| AI 인사이트, 예상 절약 가능액 | 맞춤 컨설팅, 재무 조언 |
| 새는 돈 | 랜딩 마케팅 문구에서만. 앱 안에서는 정기결제 · 이상거래로 구체적으로 |

- 예상 시간 안내는 랜딩(`보통 1분 안에 끝나고, 파일 3개는 최대 4분까지 걸릴 수 있습니다`)과 분석 중 화면(`파일 3개 기준 최대 4분`)이 같은 기대치를 말해야 한다.

### 2.4 대비 — 잉크는 다음 행동에만, 빨강은 위험에만

- **보이는 영역 하나에 활성 primary 버튼은 하나.** 나머지는 secondary나 텍스트 링크로 낮춘다.
  - 예외: 결과 화면의 잠금 카드 버튼. 문구와 목적지가 모두 같아 헷갈리지 않는다.
- `--sale`(빨강)은 에러 · 이상거래 플래그 · 회원 탈퇴에만. 지출 증가는 잉크, 감소만 `--success`.
- Pro 배지는 잉크 반전으로 Free와 구분한다. 플랜 차이를 색으로 더 꾸미지 않는다.
- **비활성 버튼은 이유를 바로 옆에 쓴다.** 대비가 낮은 버튼만 보이면 사용자는 고장이라고 생각한다. (예: `이번 달 분석 횟수를 모두 사용했습니다` + 초기화 날짜)

### 2.5 접근성 — 모든 사용자가 끝까지 갈 수 있게

**색 대비 (WCAG 2.2 AA, 본문 4.5:1 · UI 경계 3:1)**

| 토큰 | 흰 배경 | soft-cloud | 쓸 수 있는 곳 |
|---|---|---|---|
| `--ink` #111 | 18.9 | 17.3 | 모든 텍스트 |
| `--charcoal` #39393b | 11.5 | 10.6 | 모든 텍스트 |
| `--mute` #707072 | 4.94 | 4.53 | 보조 텍스트. soft-cloud 위에서는 기준에 겨우 맞으므로 12px 이하에 쓰지 않는다 |
| `--stone` #9e9ea0 | 2.67 | 2.45 | **비활성 텍스트에만.** 읽어야 하는 정보에 쓰지 않는다 |
| `--hairline` #cacacb | 1.64 | 1.50 | 텍스트 금지. 입력 테두리는 3:1에 못 미치므로 항상 라벨과 함께 쓴다 |
| `--sale` #d30005 | 5.57 | 5.11 | 에러 텍스트 |
| `--success` #007d48 | 5.21 | 4.78 | 감소 표시 |

- **색만으로 뜻을 전하지 않는다.** 증감은 `+`/`−` 부호, 이상거래는 Badge 글자, 잠금은 자물쇠 아이콘과 문구로 함께 전한다.
- **키보드만으로 가입 → 업로드 → 결과 → 업그레이드까지 갈 수 있어야 한다.** 드롭존은 `button`이고, 모달은 Esc로 닫히며 포커스가 모달 안에 머문다(탈퇴 진행 중에만 닫기 불가).
- **포커스 표시**: `:focus-visible`에 2px 잉크 outline + 2px offset. 잉크 배경 버튼에서는 offset으로 바깥에 보이게 한다.
- **상태 변화를 알린다**: 에러는 `role="alert"`, 결제 확인 · 인사이트 생성은 `role="status"`/`aria-live="polite"`, 분석 단계는 `aria-current="step"`.
- **차트**: 막대에는 `role="img"` + `aria-label`(월 · 금액), 비중 스트립 세그먼트에는 `title`.
- **아이콘**: 장식 아이콘은 `aria-hidden`, 아이콘만 있는 버튼은 `aria-label` 필수.
- **터치 타깃** 최소 36px. 375px 폭에서 가로 스크롤이 생기면 안 된다.
- **모션**: `prefers-reduced-motion: reduce`이면 막대 너비 transition과 버튼 누름 scale을 끈다.

### 2.6 근접성 — 불안 옆에 안심, 문제 옆에 해결

사용자는 가까이 있는 것을 관련 있다고 읽는다. 불안을 주는 행동 바로 옆에 안심시키는 정보를, 문제 바로 옆에 해결 방법을 둔다.

- `분석 시작` 버튼 바로 옆에 원본 저장 · 삭제 안내(자물쇠 아이콘 캡션)를 둔다.
- 에러는 원인 파일 바로 아래 박스에 파일명 · 이유 · 해결 버튼(`Pro로 업그레이드`, `대시보드 새로고침`)을 함께 둔다.
- 잠금 카드 하나에 발견 건수 · 설명 · 업그레이드 버튼을 모두 담는다.
- 사용량 미터는 `새 분석` 버튼 옆에 둔다. 한도를 보고 행동을 정하게 한다.
- **어떤 버튼을 막는 조건은 그 버튼 가까이에 둔다.** 동의해야 쓸 수 있는 버튼 바로 근처에 동의 항목이나 "아래 필수 항목에 동의하면 사용할 수 있습니다" 안내가 있어야 한다.
- 위험한 동작은 다른 동작과 떨어뜨린다. `회원 탈퇴`는 설정 맨 아래 계정 섹션에 혼자 두고, 분석 삭제는 그 행 안에서 `취소`/`삭제`로 한 번 더 확인한다.

### 2.7 정렬 — 금액은 한 줄로 맞춘다

- 레이아웃 폭과 결과 4열 그리드는 UI_GUIDE를 따른다.
- 금액은 항상 오른쪽 정렬 + `tabular-nums`이고, 라벨은 왼쪽 정렬이다. 숫자 자릿수가 세로로 맞아야 비교가 된다.
- 한 섹션 안의 콘텐츠는 왼쪽 시작선이 하나다. 섹션 헤더의 1px 잉크 선이 기준선이다.
- 목록 행은 `아이콘 | 이름(+캡션) | 금액 | 액션` 순서를 모든 목록에서 지킨다.

## 3. 단계별 설계

각 단계는 **목표 · 사용자 불안 · 규칙 · 현재 점검**으로 적는다. 현재 점검의 `개선`은 6절 백로그로 모았다.

### 3.1 방문 — 5초 안에 "무엇을 · 어떻게 · 얼마에"

- **목표**: 가입 버튼을 누르거나, 최소한 샘플 결과를 열게 한다.
- **불안**: 쓸모가 있을지 모르겠다(가치), 금융 파일을 올려도 되는지 걱정된다(신뢰).
- **규칙**
  - 히어로는 무엇(헤드라인) + 결과 모습(샘플 데이터의 실제 숫자 카드)을 한 화면에 보여준다. 기능 설명보다 결과 모습이 먼저 설득한다.
  - **가입 없이 볼 수 있는 경로(샘플 결과)를 항상 secondary CTA로 둔다.** 파일이 없거나 망설이는 방문자가 떠나지 않고 둘러볼 수 있는 길이다.
  - 신뢰 문구는 **사실만** 쓴다: 카드사 · 은행 로그인 정보가 필요 없다(파일만 올림), 원본은 본인만 접근할 수 있는 비공개 저장소에 둔다, 분석을 삭제하거나 탈퇴하면 함께 삭제된다. "은행급 보안", "완벽한 암호화"처럼 확인하지 않은 표현은 쓰지 않는다.
  - CTA는 히어로 · 요금제 · CTA 밴드에서 같은 문구로 반복한다.
- **현재 점검**
  - 확인: 히어로 2 CTA, 실제 샘플 숫자 카드, 이용 방법 3단계, 요금제 비교표
  - 반영(2026-10-03): 히어로 CTA 아래 신뢰 정보 3줄(B5), 로그인 Free의 요금제 Pro 버튼 `Pro로 업그레이드` → 결제 · Pro는 `이용 중인 플랜입니다`(B8), 샘플 결과 Pro 섹션 배지(B9). 로그인 상태의 시작 CTA는 모두 `대시보드`

### 3.2 가입 · 인증 — 묻는 것은 최소로, 막히는 곳에는 이유를

- **목표**: 인증 링크를 열어 대시보드에 도착하게 한다.
- **불안**: 절차가 번거롭다, 메일이 오지 않는다.
- **규칙**
  - Google 가입을 맨 위에 둔다(입력이 가장 적은 경로).
  - 필수 동의는 생략할 수 없으니, 동의하지 않아 비활성인 버튼 근처에서 이유를 알 수 있게 한다(2.6).
  - 인증 메일 안내에서 받는 주소를 굵게 보여주고, 재발송과 "메일이 오지 않으면 스팸함을 확인해 주세요"를 함께 둔다.
  - 인증이 끝나면 곧바로 대시보드로 간다. 중간에 환영 화면이나 튜토리얼을 넣지 않는다.
- **현재 점검**
  - 확인: Google 우선, 재발송, 다른 기기 링크 허용
  - 반영(2026-10-03): 동의 전 Google 버튼 아래 "아래 필수 항목에 동의하면 사용할 수 있습니다."(B4), 인증 메일 안내에 스팸함 문구(B15)

### 3.3 첫 분석 — 활성화 (가장 중요)

- **목표**: 가입한 날 첫 분석을 성공시킨다. (H1 실패 신호: 가입 후 첫 분석률 < 40%)
- **불안**: 파일을 어디서 받는지 모른다, 올렸다가 실패하면 시간 낭비다, 원본이 어디에 남는지 걱정된다.
- **규칙**
  - **분석 0건인 대시보드의 주인공은 드롭존이다.** 빈 상태 안내와 드롭존이 첫 화면 안에 함께 보여야 한다.
  - **파일 받는 법**을 드롭존 바로 아래 접힌 안내로 둔다(`명세서 파일은 어디서 받나요?`). 공통 순서(카드사 · 은행 앱이나 홈페이지 → 이용내역 조회 → 기간 선택 → 엑셀 또는 CSV로 저장)를 먼저 쓴다. 카드사별 메뉴 경로는 실제로 확인한 것만 추가하고, 추측한 경로는 쓰지 않는다.
  - 확장자 · 크기 · 파일 수는 서버에 보내기 전에 즉시 검증한다.
  - 기다리는 동안 무엇을 하는지(5단계)와 얼마나 걸리는지 말한다.
  - **실패는 끝이 아니라 다음 시도의 시작이다.** 모든 분석 에러는 5절의 3요소(무엇이 · 왜 · 어떻게)를 갖추고, 한도가 차감되지 않았으면 그렇다고 말한다.
  - 한도에 도달한 Free 사용자에게는 비활성 버튼 옆에 초기화 날짜와 `Pro로 업그레이드`(월 50회)를 함께 보여준다. Pro에게는 초기화 날짜만 보여준다.
- **현재 점검**
  - 확인: 즉시 검증, 파일명 포함 에러 박스, 저장 안내 근접 배치, 5단계 진행 표시, 한도 미차감 안내
  - 반영(2026-10-03): 드롭존 아래 접힌 `명세서 파일은 어디서 받나요?`(B1, 공통 순서만), 빈 상태 블록을 낮춰 1280×720에서 드롭존까지 첫 화면에 보임(B2), 빈 상태에서는 `새 분석`을 숨겨 primary를 하나로, `too_many_rows` 해결 방법(B3), 한도 도달 Free에 `Pro로 업그레이드`(B7)

### 3.4 결과 이해 — 첫 화면에 답을 준다

- **목표**: "이번 달 얼마를, 어디에 가장 많이 썼는지"를 첫 화면에서 알게 한다.
- **불안**: 분류가 맞는지 모르겠다, 그래서 무엇을 하라는 건지 모르겠다.
- **규칙**
  - KPI 4개 → 카테고리 · 가맹점 순서는 바꾸지 않는다. 숫자 계산은 결정론적 코드의 결과만 보여준다.
  - 카테고리 막대를 누르면 거래 내역이 걸러진다. 분류가 맞는지 사용자가 직접 확인하는 경로다.
  - **결과 화면의 다음 행동은 상태마다 하나다.**

  | 상태 | 다음 행동 | 위치 |
  |---|---|---|
  | Free, 정기결제나 이상거래 1건 이상 | `Pro로 업그레이드` (발견 건수 티저) | 정기결제 · 이상거래 잠금 카드 |
  | Free, 탐지 0건 | `Pro로 업그레이드` (추이 · 인사이트) | 월별 추이 · AI 인사이트 잠금 카드 |
  | Pro, 인사이트 없음 | `인사이트 생성` | AI 인사이트 패널 |
  | Pro, 거래 1개월치 | 다음 달 명세서 올리기 | 월별 추이 캡션 `다음 달 명세서를 올리면 추이가 보여요` |

  - **티저는 발견했을 때만 판다.** `0건 발견` + 업그레이드 버튼은 "Pro를 사도 볼 게 없다"는 신호가 된다. 0건이면 잠금 카드 대신 `이번 분석에서는 발견되지 않았습니다` 캡션만 두고, 업그레이드 유도는 추이 · 인사이트 잠금 카드에 맡긴다.
- **현재 점검**
  - 확인: KPI 우선 배치, 카테고리 필터, 발견 건수 티저, 1개월치 추이 안내
  - 반영(2026-10-03): 0건이면 잠금 카드 대신 `이번 분석에서는 발견되지 않았습니다`(B6)

### 3.5 업그레이드 — 가치를 본 직후에만, 압박 없이

- **목표**: 결과에서 가치를 느낀 Free 사용자를 결제까지 보낸다. (H5 실패 신호: 결제 전환 < 3%)
- **규칙**
  - 업그레이드 진입점은 **가치나 한계를 직접 겪은 순간**에만 둔다: 결과 잠금 카드, 파일 수 초과 에러, 한도 도달, 설정, 랜딩 요금제.
  - 팝업 · 전면 모달 · 카운트다운 · "지금만" 같은 압박 장치를 쓰지 않는다. 금융 도구는 신뢰가 전환보다 먼저다.
  - 잠금 카드에 가짜 데이터를 흐리게 깔지 않는다(UI_GUIDE). 진짜 발견 건수가 가장 강한 근거다.
  - 결제 후 돌아오면 `결제 확인 중` → `Pro가 활성화됐습니다` 토스트로 끝맺는다. **기다림에는 반드시 끝 상태가 있어야 한다.** 자동 확인을 멈췄는데 아직 Free면 스피너를 계속 돌리지 말고 "확인이 늦어지고 있습니다. 잠시 후 새로고침해 주세요."와 새로고침 버튼으로 바꾼다.
- **현재 점검**
  - 확인: 잠금 카드에서 바로 Checkout, 결제 확인 자동 새로고침, 활성화 토스트
  - 반영(2026-10-03): 자동 확인이 끝나도 Free면 지연 안내 + `새로고침` 버튼(B10)

### 3.6 재방문 — 다음 달에 올릴 이유를 남긴다

- **목표**: 2개월 차에도 분석하게 한다. (H7 실패 신호: 2개월 차 재분석 < 30%)
- **규칙**
  - 리마인더 메일은 H7 실패 신호가 확인되기 전에는 만들지 않는다(USER_FLOW 8절).
  - 앱 안에서 다음 달 이유를 보여준다: Pro는 1개월치 추이 캡션, Free는 월별 추이 잠금 카드.
  - 대시보드는 최신 분석이 맨 위에 오고, 각 행에 총지출을 보여 지난달과 바로 비교되게 한다.
- **현재 점검**: 확인. 추가 장치는 H7 신호를 확인한 뒤 검토한다(백로그 "선택")

### 3.7 해지 · 탈퇴 — 떠나는 길도 분명하게

- 해지 경로를 숨기지 않는다. 설정 → `구독 관리`(Polar 포털) 한 번이면 닿아야 한다.
- 해지 전후 불안(데이터가 사라질까)을 문구로 줄인다: "해지해도 과거 분석은 계속 볼 수 있습니다. Pro 전용 항목만 다시 잠깁니다." (결과는 현재 플랜으로 `toAnalysisView`를 거치므로 "그대로"라고 쓰지 않는다)
- 회원 탈퇴는 처리 순서를 미리 보여주고 `탈퇴` 입력으로 한 번 더 확인한다.
- **현재 점검**
  - 확인: `구독 관리` 한 번에 포털 이동, 해지 예약 시 `N까지 Pro` 표시, 탈퇴 처리 순서 · 입력 확인
  - 반영(2026-10-03): 구독 영역에 해지 후 데이터 유지 안내(B16)

## 4. 화면 상태 체크리스트

새 화면이나 컴포넌트를 만들 때 아래 상태를 모두 설계한다. 빠진 상태는 대부분 막다른 길이 된다.

| 상태 | 규칙 | 현재 예 |
|---|---|---|
| 비어 있음 | 무엇을 하면 채워지는지 + 그 행동 버튼 | 대시보드 빈 상태, `발견된 정기결제가 없습니다.` |
| 로딩 (1초 이상) | 지금 무엇을 하는지 말한다 | 분석 5단계, `거래 N건을 살펴보는 중…` |
| 오래 걸림 · 시간 초과 | 끝 상태와 다음 행동을 둔다. 끝없는 스피너 금지 | `timeout` 에러, 결제 확인(개선 필요) |
| 에러 | 무엇이 · 왜 · 어떻게 + 다시 시도 경로 | 업로드 에러 박스, 인사이트 `다시 시도` |
| 잠김 (Free) | 무엇이 잠겼는지 + 발견 건수 + 업그레이드 | LockCard |
| 비활성 | 이유를 버튼 옆에 | 한도 초과 `분석 시작` |
| 완료 | 결과 화면으로 이동하거나 토스트로 알린다 | 분석 완료 → 결과, `Pro가 활성화됐습니다` |
| 위험 동작 | 인라인 확인 또는 입력 확인 | 분석 삭제 `취소`/`삭제`, 탈퇴 모달 |

## 5. 문구 규칙

- 존댓말 `-습니다` / `-해 주세요`. 한 문장에 정보 하나.
- **에러 문구 3요소**: 무엇이 안 됐는지 → (필요하면) 왜 → 어떻게 하면 되는지. 사용자를 탓하지 않는다("잘못된 파일입니다" 대신 "거래내역을 찾을 수 없습니다. 카드 명세서나 은행 거래내역 파일을 올려 주세요.").
- 돈 · 횟수와 관련된 결과는 반드시 말한다: "분석 횟수는 차감되지 않았습니다", "삭제해도 복구되지 않습니다".
- 숫자는 구체적으로: `3건 발견`, `월 ₩42,000`, `2 / 5회`. "몇 건", "일부" 같은 말을 쓰지 않는다.
- 버튼은 동작으로 끝낸다: `분석 시작`, `Pro로 업그레이드`, `인사이트 생성`. `확인` · `예`만 단독으로 쓰지 않는다(위험 동작은 `삭제`, `탈퇴하기`처럼 동작을 쓴다).
- 공포 · 과장 마케팅 금지: "돈이 새고 있습니다!", 느낌표, 이모지 금지.
- 에러 문구는 `src/messages/errors.ts`에만 둔다.

## 7. 검증
