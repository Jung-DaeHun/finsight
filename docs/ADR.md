# Architecture Decision Records

## 철학
MVP 속도 최우선. 관리형 서비스(Supabase, Vercel, Polar)로 인프라를 최소화한다. 금융 데이터를 다루므로 속도를 위해 보안(RLS, 서버 전용 키, 웹훅 서명 검증)을 타협하지 않는다. LLM은 판단이 필요한 곳에만 쓰고, 계산은 코드로 한다.

---

### ADR-001: Next.js App Router + TypeScript + Tailwind
**결정**: Next.js(App Router) 단일 앱으로 프론트와 API를 함께 구성한다.
**이유**: 별도 백엔드 없이 Route Handler로 충분하고, Vercel 배포와 궁합이 가장 좋다. `after()`로 응답 후 비동기 작업을 돌릴 수 있어 큐 없이 분석 파이프라인을 처리할 수 있다.
**트레이드오프**: 장시간 작업은 Vercel 함수 실행 시간 제한을 받는다. 1,000행 한도로 제한 내에 들어오게 설계한다.

### ADR-002: Supabase (Auth + Postgres + Storage)
**결정**: 인증, DB, 파일 저장을 모두 Supabase로 처리한다.
**이유**: 이메일/비밀번호와 Google 로그인을 바로 지원하고, RLS로 사용자 데이터를 DB 레벨에서 격리할 수 있다. 서비스 하나로 세 가지를 해결한다.
**트레이드오프**: Supabase에 종속된다. 복잡한 백그라운드 잡이 필요해지면 별도 큐를 붙여야 한다.

### ADR-003: 결제는 Polar
**결정**: Polar 구독(Pro $9/월)을 사용한다.
**이유**: Merchant of Record라 해외 부가세·세금 처리를 대신 해준다. Next.js용 Checkout/Webhook 헬퍼가 있어 연동이 간단하다.
**트레이드오프**: 결제 통화가 USD 기준이라 한국 사용자에게 원화 결제 경험을 제공하지 못한다. 국내 PG(토스페이먼츠 등)는 MVP 이후 검토한다.

### ADR-004: LLM은 Claude 단일 프로바이더
**결정**: Claude API만 사용한다. 컬럼 매핑·카테고리 분류는 저비용 모델(Haiku 계열), 인사이트 생성은 상위 모델(Sonnet 계열)을 쓰고, 모델 ID는 `services/claude.ts` 상수로 관리한다.
**이유**: 프로바이더 추상화 계층 없이 코드와 테스트가 단순해진다. 작업 난이도별로 모델을 나눠 비용을 줄인다.
**트레이드오프**: Anthropic 장애 시 대체 수단이 없다.

### ADR-005: LLM 호출 최소화 전략
**결정**: (1) 컬럼 매핑은 헤더 + 샘플 5행만 보낸다. (2) 분류는 행이 아니라 고유 가맹점 단위로 배치 요청한다. (3) 합계·추이·정기결제·이상거래는 결정론적 코드로 계산한다.
**이유**: 비용과 지연을 줄이고, 계산 결과를 테스트로 검증할 수 있다. LLM이 숫자를 틀리게 계산하는 위험을 없앤다.
**트레이드오프**: 규칙 기반 탐지는 LLM보다 유연하지 않다. 샘플 5행으로 매핑이 틀리면 전체 파싱이 실패할 수 있으므로 정규화 실패율이 높으면 `failed`로 처리하고 사용자에게 알린다.

### ADR-006: 원본 CSV 저장
**결정**: 원본 CSV를 Supabase Storage private 버킷에 사용자별 경로로 저장한다.
**이유**: 파싱 로직 개선 시 재분석이 가능하고, 분석 오류를 디버깅할 수 있다.
**트레이드오프**: 민감한 금융 원본을 보관하는 책임이 생긴다. 완화책: private 버킷 + 경로 기반 RLS, 사용자 데이터 전체 삭제 기능, 업로드 화면과 개인정보 처리방침에 저장 사실 명시, 로그에 CSV 내용을 남기지 않는다. Free는 최근 1건만 보관한다.

### ADR-007: Free/Pro는 기능으로 구분
**결정**: 사용량이 아닌 기능으로 플랜을 나눈다. 월간 분석 상한(Free 5회, Pro 50회)은 남용 방지용으로만 둔다.
**이유**: 명세서는 월 1회 나오므로 횟수 제한은 차별점이 되지 않는다. 누적 비교, 여러 카드 통합, 탐지, AI 조언은 반복 사용할수록 가치가 커지는 기능이다.
**트레이드오프**: Free 사용자도 매 분석마다 LLM 비용(매핑+분류)이 발생한다.

### ADR-008: 다국어는 next-intl, 경로 기반 로케일
**결정**: `next-intl`로 `/ko`, `/en` 경로 기반 라우팅을 쓴다.
**이유**: App Router와 Server Components를 공식 지원하고, URL로 언어가 결정되어 SEO와 공유에 유리하다.
**트레이드오프**: 모든 페이지가 `[locale]` 세그먼트 아래로 들어가 구조가 한 단계 깊어진다.

### ADR-009: 테스트는 Vitest
**결정**: Vitest + Testing Library를 쓴다. E2E(Playwright)는 MVP에서 제외한다.
**이유**: 설정이 가볍고 빠르다. 핵심 로직(`lib/`)이 순수 함수라 단위 테스트로 대부분 커버된다.
**트레이드오프**: 인증·결제의 전체 흐름은 수동 검증에 의존한다.
